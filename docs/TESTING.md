## 版本验证范围

已发布的 0.6.0 Standalone / ASI 曾通过使用者实机验证。该记录不自动延伸为当前源码更新的完整实机验收。自动回归使用合成对象、私有测试窗口和临时目录，覆盖安全帧事务、角色队列和补足、八语文案与名称解析、独立窗口、输入共存及双分发安装保护。

当前独立源码采用两个入口共用的运行时与页面。2026-09-30 的 Windows x64 全新构建已通过 **35 项 CTest**，包括真实配置、页面、安全队列、两入口、安装边界和 Present 链回归。真实业务页的离屏 WARP 截图覆盖普通分辨率和 1280×720 功能设置、角色确认、快捷键页面；后备页夹具还验证方向导航能完整显示确认按钮，第一次确认不提交角色变化。截图和自动测试不等同于游戏内、存档或实体手柄验收。

快捷键回归覆盖 UTF-8 配置保存与重载、未知项保留、损坏和重复配置、硬链接拒写、写入失败、跨 DLL 冲突和并发预留；输入回归覆盖精确修饰键、改绑松键保护、斜方向拒绝、跨槽镜像、250 毫秒缓存过期、渲染故障放行与失焦保留。完整用例和运行方式见[构建指南](BUILDING.md#测试)。

发行变化见 [0.6.0 发行说明](https://github.com/blockshy/sky2-party-editor/releases/tag/v0.6.0)。当前源码更新不替换原发行附件。

## Standalone / ASI 没有面板时

1. 确认安装的是发行包而非 Source code，并按[安装结构](INSTALLATION.md#手动安装)核对文件，没有额外的 dist 层级，也没有同时放入两种队伍入口。
2. 进入普通探索，先试 F8。ASI 版须先有可正常加载插件的 Ultimate ASI Loader；公共 Loader 与其他 Mod 的同名 DLL 不能互相覆盖。
3. 检查对应数据目录的 `party.log`：独立版位于 `Sky2PartyEditor/`，ASI 版位于 `plugins/Sky2PartyEditor/`。若记录版本不支持，核对[游戏 EXE 哈希](INSTALLATION.md#兼容版本)，不要跳过验证。
4. 核对 `settings.ini` 中 `Enabled` 没有设为 0。手动编辑设置后需要重启。
5. 若 F8 可用而手柄入口不可用，按面板提示用键盘操作，并记录手柄、Steam Input 设置和同时安装的 Mod，供兼容性排查。

## 当前独立窗口与输入验收

以下是当前源码构建的实机验收步骤。生产输入隔离测试和离屏截图只覆盖合成环境，不能直接把此表记为实机通过。

| 检查 | 预期 |
| --- | --- |
| F8 / View + 十字键左 开关，关闭后按键和鼠标正常操作游戏 | 每次只切换一次，不因保留 VK7 一直吞键 |
| Ctrl / Alt / Shift / Win + F8；先松修饰键、继续按住 F8 | 不打开队伍窗口、不补触发；彻底松开后单独新按 F8 才生效 |
| View + 左上 / 左下 / 左右；旧 F11 / View + LS | 不打开当前队伍窗口；只有单一十字键左与 View 的组合有效 |
| LB/RB / PgUp/PgDn 与 LT/RT / Ctrl+PgUp/PgDn | 分别切侧栏和页签；黄色焦点只在 Main |
| 十字键/左摇杆方向、A/Enter、B/Esc、右摇杆滚动 | 导航、确认、返回正确；固定区域不随 Main 滚动 |
| 鼠标拖动标题，切换 1280×720 与常用分辨率 | 位置保留并限制在客户区内；底部提示可见 |
| 角色确认一次后切页、切侧栏或 Alt+Tab | 确认取消；后台窗口仍显示且只读 |
| 失焦期间按住 Enter、A、F8，再回游戏 | 不触发旧按压；松开后新按压恢复操作 |
| 不再收到游戏手柄样本 | 250 毫秒后释放导航状态，键鼠仍可用，不另读物理控制器 |
| 三个采用合作协议的新 ASI 依次打开窗口 | 新窗口取得输入，旧窗口关闭；退出后游戏操作恢复，单按 View 保留原功能 |
| 在“快捷键”修改主键、修饰键或手柄按钮，保存后松键 | 新绑定生效，旧绑定释放；旧按压不补触发 |
| 设置与另一个已加载 Mod 相同的键盘或手柄组合 | 显示占用模块和动作，保存被拒绝，不更改对方设置 |
| 清空队伍窗口键盘入口；恢复被其它 Mod 占用的默认组合 | 均拒绝提交，保持当前可用入口 |
| 选择键位子列表、返回、切侧栏及失焦 | 导航可达；离页撤销草稿，后台只读且角色确认已取消 |
| 手工 INI 冲突或损坏，重启游戏 | 使用可用默认/备用入口，日志写出 Window shortcut；原文件不自动覆盖 |

## 历史 0.6.0 独立面板回归

| 检查 | 预期 |
| --- | --- |
| F11 与 View + LS 各开关两次 | 每次按下只切换一次，没有 Xbox 弹窗 |
| 方向键 / 十字键、Enter / A、Esc / B | 选择、确认和关闭正确，面板内不同时操作游戏 |
| 鼠标停在一行，改用键盘/手柄选择其他行或滚动 | 仅当前选中项目显示绿色条 |
| 组合键先后释放、关闭时仍按住确认键 | 不重复切换，关闭后剩余按压不误触游戏 |
| 键盘与手柄交替、手柄断开重连 | 提示随输入切换，重连后可再次操作 |
| 按住鼠标后用 F11 关闭，再释放并重开 | 无残留按下、拖动或自动点击 |

ASI 与宝箱插件共用时，分别打开两个面板，关闭队伍面板后再操作宝箱清单、暂停与传送。确认两个插件都持续工作，短按 View 保持原功能。其他 Loader/插件组合需独立验证。

## 八语界面回归

1. 依次在游戏设置中选择简中、繁中、日、英、德、法、西、韩文字语言，确认应用后用 F8 打开当前源码的独立面板。标题、开关、状态、操作结果和快捷键说明应随之切换；只修改语音时界面不应切换。
2. 核对角色完整名称与同语言原生编成页一致，包括称谓、军衔与重音符号；不应混入另一语言的名称。
3. 关闭面板后切换语言再打开，核对上次选中角色身份没有变化，最近结果不残留旧语言。正常关闭、切换项目及确认超时仍取消待确认操作。
4. 在 1280×720 与常用分辨率下，分别检查键盘/手柄提示、长名称、等待状态、固定队员警示和数据补足说明；文字不应重叠，列表能够滚动，底部按键完整可见。
5. 重启游戏或读取其他存档后复查当前文字语言。若缺字，安装对应 Windows 补充字体后重试；若出现角色编号，提供资源读取失败的日志，不提交游戏文本表。

语言验证本身不需要加入角色或改动存档。完整功能回归按下一节执行。

## 功能回归

1. 在普通探索逐项关闭、开启前三项。检查协会外原生队伍键入口、固定成员互换及暂不可选后备；关闭功能后应恢复对应限制。
2. 在原生菜单中提交设置，关闭菜单返回探索后检查是否应用。战斗、过场、换图时不得执行角色加入；剧情编成锁仍应限制操作。
3. 退出重启，核对开关保留。关闭开关不应自动改回之前的队伍。
4. 开启实验功能，确认角色一次后换行或关闭面板，应取消加入；同一项目再次确认两次才执行。
5. 分别检查完整数据角色、隐藏后备、缺少武器/战技角色和未初始化角色。未初始化角色应保持不可加入，已有可见成员不得重复新增。
6. 加入后通过原生编成换入主力，检查等级、装备、回路、普通战技及 S 战技，再验证跟随、换图、普通战斗与结算。主力不超过四人，已有角色不应被自动移除。
7. 将结果另存后读取，核对队伍和培养；再读修改前存档，确认不会自动重做上次加入。

继承档还应检查“空战技列表但保留 S 战技选择”的角色：补足后原有 S 战技应可用，已有等级、经验、装备和回路应保持。乔丝特的原有剧情 S 战技也需单独核对，不能只根据头像出现判断角色已完整可用。

## 卸载回归

用独立存档把固定成员换到后备，面板应提示角色及所属队伍，此时关闭“解除固定队员”应被拒绝。通过原生编成换回主力后，再关闭开关并保存；退出卸载，重新读档检查原版可见性。完整恢复方法见[卸载前恢复](INSTALLATION.md#卸载前恢复固定队员)。

独立版和 ASI 版应分别检查：手动安装后脚本卸载、脚本安装后手动卸载、同分发更新，以及按说明切换分发。未知同名文件应拒绝覆盖/删除，自己的配置、日志与其他插件应保留。安装自动测试只在临时目录执行，不应拿真实游戏目录试破坏性边界。

## 反馈问题

通过 [GitHub Issues](https://github.com/blockshy/sky2-party-editor/issues) 提供：

- Mod 版本、Standalone / ASI、游戏 EXE 哈希；ASI 另附 Loader 及其他插件版本。
- 键盘/手柄类型、Steam Input 是否启用、实际按键与最小复现步骤。
- 章节、地点、角色及原状态，问题发生在探索、菜单、战斗还是存取档环节。
- 面板提示截图及 `party.log` 中相关片段；公开前删除个人路径等信息。

若提示“数据已部分补足”，停止对该角色重复尝试；该提示不代表回滚。日志的 `Roster preparation` 记录包含角色、阶段及是否开始原生处理，可帮助区分学习、继承 S 技恢复和装备环节。优先读取原始存档继续游戏。

不需要公开完整存档、游戏资源或内存转储。提交开发改动时，自动测试方法见[构建指南](https://github.com/blockshy/sky2-party-editor/blob/main/docs/BUILDING.md#测试)。
